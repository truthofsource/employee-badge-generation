# Employee badge generation walkthrough

## 1. Resolve the employee and source

HR/Admin selects the employee. The application resolves the current profile and either a previously authorized ID image or a separate headshot. The actual source rule requires the correct employee, one current candidate, read permission and exact scan proof. A headshot remains an independent fallback when the ID portrait is unavailable.

```bash
npm run test:source
```

The extracted source tests use fictional records. They do not read a real identity document.

## 2. Prepare the portrait

The implemented process uses AI-assisted main-portrait extraction and cleanup, a neutral-gray background and source appearance/hairstyle preservation. Names, title and logo are not generated by AI. A separate headshot is appropriate when essential detail is obscured; generation cannot establish what hidden facial detail looked like.

The public optional adapter models the image-edit request and response boundary. Its tests mock the provider:

```bash
python -B -m unittest discover -s tests -p test_portrait_ai.py -v
```

## 3. Render the fixed design

The renderer takes trusted profile name/title and prepared portrait, fits the image without stretching, and writes PNG plus a PDF at 3.375 x 2.125 inches. The public illustration/template is fictional; the actual deployment uses its approved organization artwork.

```bash
python -B -m lab render --out .local/badge-preview
```

Print the PDF at actual size / 100%, not fit-to-page. The public page-size test is not a claim that this new sample was physically printed.

## 4. Validate and issue

The actual issue function rechecks the current profile/draft/source/template fingerprint and both artifact scan proofs. Direct issue performs automatic validation and stores the issued version; a human comparison gate is not mandatory. Changes to the employee, portrait, crop or template invalidate an old preparation.

## 5. Reprint, employee access and revoke

Reprint returns stored issued files rather than re-rendering or calling AI again. The employee endpoint resolves ownership from the signed-in account, exposes only a limited current-badge projection and denies revoked, foreign or unverified files. Revocation stops future release; it cannot recall a previously downloaded or printed copy.

The source lifecycle/self-service tests exercise these decisions through in-memory repository ports. A hosted database lock, actual Blob reads and Entra session acceptance remain separate integration evidence.
